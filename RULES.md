# Rule index

Generated by `dotnet fsi scripts/check.fsx` from the rule files. Do not edit by hand.

One line per rule: its core sentence. Agents that write code load this file and open a rule file when
they touch its subject or need its exceptions. Reviewers read the full rule, investigate its search
patterns, and establish the report conditions before raising a finding.

## Formatting

- [Leave layout to the formatter](rules/formatting/formatter-owns-layout.md) - Write new code in the layout Fantomas produces with the repository's `.editorconfig`, and change the layout only of lines whose content you change.
- [Put multiline brackets on lines of their own](rules/formatting/multiline-brackets-aligned.md) - Write a record, anonymous record, or list either on one line or with the opening bracket on its own line, the content indented one level, and the closing bracket on its own line. (formatter or linter) Pick one: alternative to `multiline-brackets-stroustrup`.
- [Open multiline brackets at the end of the line](rules/formatting/multiline-brackets-stroustrup.md) - Write a record, anonymous record, or list either on one line or with the opening bracket at the end of the binding line, the content indented one level, and the closing bracket on its own line. (formatter or linter) Pick one: alternative to `multiline-brackets-aligned`.
- [Write punctuation you can type](rules/formatting/plain-keyboard-characters.md) - Use plain keyboard punctuation in code, comments, and string literals: `-`, `->`, `...`, and straight quotes instead of typographic dashes, arrows, ellipses, and curly quotes. (formatter or linter)

## Naming and comments

- [Use as for views and to for transformations](rules/naming/as-vs-to-conversions.md) - Name a conversion `asX` only when it changes the view of the same data, such as a cast or a wrapper without copying, and `toX` when it computes new data in another format, unit, or domain.
- [Follow the F# casing conventions](rules/naming/casing-conventions.md) - Use PascalCase for namespaces, modules, types, union cases, and members, and camelCase for let-bound values, functions, and parameters; choose one casing for record fields per code base and keep it. (formatter or linter)
- [Comment only what the code cannot say](rules/naming/comments-say-why.md) - Write a comment only for what names and types cannot express, such as a constraint of an external system or the reason for a surprising decision, in one or two plain lines.
- [Name text projections instead of overriding ToString](rules/naming/describe-instead-of-tostring.md) - Give a type a named member such as `Description` for its display text instead of overriding `ToString`.
- [Name functions after what they return](rules/naming/name-by-result.md) - Name a function after its result or its effect and a value after its content, so that the call site tells what comes back and from which side.

## Scope and structure

- [Resolve dependency cycles instead of using rec](rules/scope/compile-order-without-rec.md) - Declare dependencies before their users and resolve avoidable cycles through structure rather than recursive modules or groups.
- [Hide what is not part of a module's purpose](rules/scope/hide-implementation-details.md) - Mark module-only helpers private and choose a library's public surface deliberately, using signature files when many internals need hiding. Pick one: alternative to `no-access-modifiers`.
- [Keep module initialization free of I/O](rules/scope/keep-module-initialization-pure.md) - Perform I/O in functions that startup code calls explicitly rather than in module-level values.
- [Nest single-use bindings in their consumer](rules/scope/nest-single-use-bindings.md) - Declare a helper used by only one function inside that function, after its dependencies and before its users. Pick one: alternative to `top-level-helpers`.
- [Leave access modifiers out](rules/scope/no-access-modifiers.md) - Write functions, values, types, and modules without access modifiers, retaining private cases on validated single-case unions. Pick one: alternative to `hide-implementation-details`.
- [Require qualified access for generic names](rules/scope/require-qualified-access.md) - Mark unions and modules with generic names RequireQualifiedAccess instead of relying on unqualified names or manual prefixes.
- [Keep a resource alive for the work that uses it](rules/scope/scope-owned-resources.md) - Dispose owned resources and keep their ownership scope around all work that reads them.
- [Shadow successive versions of a value](rules/scope/shadow-successive-versions.md) - Rebind successive replacements under the same name when later code needs only the current version.
- [Keep helper functions flat at module level](rules/scope/top-level-helpers.md) - Declare substantial named helper functions at module level directly above their consumer when they do not capture the consumer's local values. Pick one: alternative to `nest-single-use-bindings`.

## Types and domain modeling

- [Reject contradictory input in constructors](rules/types/constructors-reject-contradictions.md) - Make constructors and conversions into validated domain types reject input they cannot represent faithfully instead of silently guessing a valid state.
- [Treat empty text as missing where it enters](rules/types/empty-text-is-missing.md) - Convert null, empty, and whitespace-only text into one option representation at entry when the domain treats all three as missing.
- [Use F# collections in domain types and signatures](rules/types/fsharp-collections-in-domain-types.md) - Use immutable F# collections in domain fields and signatures instead of exposing mutable collection objects.
- [Make illegal states unrepresentable](rules/types/illegal-states-unrepresentable.md) - Choose domain data shapes that exclude forbidden combinations rather than relying on flags, optional fields, or string keys to agree at runtime.
- [Represent money as a type, not as raw numbers](rules/types/money-not-raw-numbers.md) - Carry money between domain operations as decimal amounts with currency, converting to checked minor units only at storage boundaries.
- [Name the cases instead of using bool or Choice](rules/types/name-the-cases.md) - Represent domain alternatives with named union cases, and pass an existing domain distinction instead of reducing it to a boolean flag.
- [Return a union when None has several reasons](rules/types/one-reason-per-none.md) - Return named outcomes instead of option when different reasons for absence require different caller behavior or diagnostic information.
- [Use option for missing values, not null](rules/types/option-not-null.md) - Represent missing domain values as option, or value option on measured hot paths, and convert .NET absence at the boundary.
- [Attach units of measure to quantities that meet other units](rules/types/units-of-measure.md) - Use units of measure when numeric quantities of different units or scales meet in the same code.
- [Wrap constrained primitives and identifiers in single-case unions](rules/types/wrap-constrained-primitives.md) - Give constrained primitives private validated wrappers and give confusable entity identifiers distinct single-case unions with total construction.

## Functions and control flow

- [Name a repeated distinction with an active pattern](rules/functions/active-patterns-for-repeated-distinctions.md) - Give a distinction that several matches repeat, such as which plans include an admin area, a name as a complete active pattern, instead of grouping the same cases or testing the same condition in every match.
- [Annotate types only where inference needs it](rules/functions/annotate-only-where-needed.md) - Write a type annotation only where the compiler needs it, not for clarity or out of habit, and decide by removing it and building. Pick one: alternative to `annotate-public-signatures`.
- [Annotate the signatures of public functions](rules/functions/annotate-public-signatures.md) - Annotate parameter and return types of functions that other modules call, and leave local code and lambdas to inference. Pick one: alternative to `annotate-only-where-needed`.
- [Build lists without appending to a growing list](rules/functions/build-lists-without-repeated-append.md) - Build a list with a list expression, or by prepending and reversing, instead of appending to it in a loop or recursion.
- [Compose short internal transformations directly](rules/functions/compose-small-internal-functions.md) - Define a short function that only its own module uses as a typed composition or partial application when its steps and input type are evident. Pick one: alternative to `name-the-data`.
- [Confine mutation to the block that builds a value](rules/functions/confine-mutation.md) - Use `let mutable` or a mutable collection only inside the block that computes a value, so that only the finished, immutable result leaves it.
- [Curry module functions and tuple members](rules/functions/curry-functions-tuple-members.md) - Give functions in modules curried parameters, ordered from the least to the most varying with the piped data last, and give members of types that .NET code calls tupled parameters.
- [Enumerate effectful sequences once](rules/functions/enumerate-effectful-sequences-once.md) - Materialize a sequence that reads files, queries a database, or has other effects into a list or array when more than one consumer needs its elements.
- [Fold cohesive state without mutation](rules/functions/fold-cohesive-state.md) - Write a reduction whose state belongs together, including a tuple or record accumulator, as a pure fold instead of a loop over mutable variables. Pick one: alternative to `loops-over-compound-folds`.
- [Build strings with interpolation](rules/functions/interpolation-over-sprintf.md) - Build strings with interpolated strings such as `$"Order {order.id} shipped"` instead of `sprintf`, `failwithf`, `String.Format`, or chains of `+`.
- [Prefer simple reductions over compound folds](rules/functions/loops-over-compound-folds.md) - Replace a `fold` whose accumulator is a tuple or record, and every `||>` fold, by specific functions such as `sumBy`, `partition`, or `groupBy`, a comprehension, or a `for` loop over a confined `let mutable`. Pick one: alternative to `fold-cohesive-state`.
- [Distinguish domain cases with match](rules/functions/match-domain-cases.md) - Use `match` when code decides between domain cases, also for two cases, instead of `if`/`elif` chains or `.IsCase` properties.
- [Name the data instead of composing point-free](rules/functions/name-the-data.md) - Define module-level functions with named parameters and a pipeline, not as point-free compositions with `>>` or partial applications. Pick one: alternative to `compose-small-internal-functions`.
- [Apply a function before you interpolate it](rules/functions/never-interpolate-functions.md) - Interpolate only values, apply a function before its result goes into a string, and treat warning FS3884 as an error.
- [Spell out every case of your own unions](rules/functions/no-wildcard-over-own-unions.md) - Write every case of a union defined in your code base in a match, grouping cases with the same result as or-patterns, instead of collecting them in a `| _ ->` branch.
- [Define operators only as aliases of named functions](rules/functions/operators-as-named-aliases.md) - Define a custom operator only in a module that is opened on purpose, such as a DSL or combinator module, and only as a one-line alias of a named function that callers can use instead.
- [Pipe straight chains, bind named steps in a computation expression](rules/functions/pipe-or-computation-expression.md) - Write a straight chain of `Option`, `Result`, or `Task` steps that each take the previous result as a pipeline, and use a computation expression when a step needs an earlier result by name or the pipeline would nest lambdas.
- [Access members without a lambda](rules/functions/shorthand-member-access.md) - Write a lambda that only reads a member as `_.Name`, available since F# 8, and read a member of a single value directly instead of piping the value into a lambda.
- [Transform options with combinators, not by testing and reading](rules/functions/use-option-combinators.md) - Use `Option.map`, `Option.bind`, `Option.defaultValue`, `Option.defaultWith`, or a `match` instead of testing `IsSome` and then reading `.Value`, and instead of writing such a combinator out as a match.

## Errors

- [Avoid functions that throw on missing data](rules/errors/avoid-partial-functions.md) - Use `tryHead`, `tryFind`, `tryItem`, `tryExactlyOne`, `Map.tryFind`, or a match instead of `List.head`, `List.find`, `Seq.exactlyOne`, `Map.find`, `Option.get`, or `.Value` on an option when the input can break their preconditions.
- [Catch exceptions only at boundaries](rules/errors/catch-at-boundaries.md) - Write `try`/`with` only directly around a call that throws for an expected reason, such as parsing, a file, an SDK, or legacy code, and classify the exception right there; never wrap your own core logic or swallow exceptions.
- [Return expected failures as values, not exceptions](rules/errors/expected-failures-are-values.md) - Return a business failure that callers handle, such as invalid input, an unknown key, or a violated rule, as `Result` or `Option` instead of `failwith`, `raise`, or `invalidOp`.
- [Decide per kind of data whether a failure stops, drops, or degrades](rules/errors/fail-or-degrade-per-datum.md) - Decide for each kind of loaded data whether a failure stops the operation, drops the item with a warning, or falls back to a default, and make that decision in the workflow.
- [Report input errors as a union, map them to fields in the view](rules/errors/field-errors-as-union.md) - Report invalid input as a union with one case per situation, and map each case to its field and message in exactly one exhaustive match in the view.
- [Let cancellation remain cancellation](rules/errors/preserve-cancellation.md) - Let `OperationCanceledException` propagate instead of turning it into a business error, a fallback value, or a retry.
- [Rethrow with reraise](rules/errors/reraise-keeps-stack.md) - Rethrow the exception being handled with `reraise ()`, or with `ExceptionDispatchInfo.Capture(ex).Throw()` inside computation expressions where `reraise` does not compile, and wrap it only to add context, passing the original as inner exception.
- [Return Result only for failures a caller acts on](rules/errors/result-for-decisions.md) - Use a `Result` error case only when some caller matches on it and does something different, and let failures nobody can handle, such as an unavailable database, raise exceptions caught once at the top.
- [Report a unique-index collision as a field error](rules/errors/unique-violation-is-a-field-error.md) - Check for an existing row with the same filter that the unique index uses before an insert, return a field error on a collision, and map the unique violation that the insert can still raise to the same error.

## Async

- [Await asynchronous work without blocking](rules/async/avoid-blocking-on-tasks.md) - Wait for a task with `let!` or `do!` instead of `.Result`, `.Wait()`, `GetAwaiter().GetResult()`, or `Async.RunSynchronously`.
- [Await every task whose work you own](rules/async/await-owned-tasks.md) - Await or return every task whose completion belongs to the current operation, instead of discarding it with `ignore` or `let _ =`.
- [Keep synchronous code synchronous](rules/async/keep-synchronous-code-synchronous.md) - Return a plain value from a function that awaits nothing, and wrap it into a task only where a signature requires one, with `Task.FromResult` or inside an existing `task`.
- [Start a fresh task for every retry](rules/async/recreate-tasks-for-retries.md) - Pass a function that starts the task to a retry loop and call it for every attempt.
- [Start independent awaits together](rules/async/start-independent-awaits-together.md) - Bind independent asynchronous calls with `and!`, which current FSharp.Core supports in `task` and FsToolkit in `taskResult`, or start their tasks before the first `let!`, instead of awaiting them one after the other.
- [Use task for I/O in .NET applications](rules/async/task-for-dotnet-io.md) - Write asynchronous application code that calls .NET APIs as `task { }`, pass a `CancellationToken` explicitly where work must be cancellable, and use `async { }` only where its cold start or implicit cancellation is needed.

## Design

- [Generalize only for a second real use](rules/design/abstract-on-second-use.md) - Generalize domain code for reuse only when a second real use exists, and let small incidental blocks repeat until then.
- [Group configured operations in immutable classes](rules/design/classes-for-configured-logic.md) - Use a small immutable class when its constructor fixes settings that a cohesive group of operations shares and callers reuse that configuration. Pick one: alternative to `modules-for-logic`.
- [Keep F# APIs idiomatic and add a facade for C#](rules/design/csharp-facade.md) - Write APIs that F# code calls with F# types, and add a separate facade that converts to .NET types when C# code consumes the library.
- [Keep types as data and functions in a companion module](rules/design/functions-in-companion-module.md) - Define records and unions as plain data and put their functions, including construction and projections, in a module of the same name directly after the type. Pick one: alternative to `members-for-own-data`.
- [Pass a function or a value instead of a single-use interface](rules/design/functions-over-single-use-interfaces.md) - Take a dependency as a function or the value it produces instead of defining an interface for one operation and one implementation.
- [Keep I/O at the edges of a workflow](rules/design/io-at-the-edges.md) - Structure a workflow as read, decide, write: load data, compute the decision in a pure function, then perform the effects that decision describes.
- [Put on a type what needs only its own data](rules/design/members-for-own-data.md) - Define construction, projections, and state transitions that use only a type's own data as members, and put I/O and workflows over several types into modules. Pick one: alternative to `functions-in-companion-module`.
- [Use modules for logic and classes only for state with a lifetime](rules/design/modules-for-logic.md) - Write logic as functions over records and unions, and reserve classes for state, resource ownership, lifetimes, or required framework contracts. Pick one: alternative to `classes-for-configured-logic`.

## Tests

- [Assert the exact error, not just that one occurred](rules/tests/assert-exact-error-values.md) - Compare a failing result with the exact error value it must contain, instead of only checking that some error came back.
- [Prove that a rejected input writes nothing](rules/tests/assert-nothing-written-on-rejection.md) - Give every workflow that writes a test showing that a rejected input leaves storage untouched, in addition to the test of the error value.
- [Give every setup its own test](rules/tests/one-setup-per-test.md) - Write one test per setup, and generate a named test per input from a list when the same assertion applies to several known inputs.
- [Assert what the test name says, nothing else](rules/tests/test-name-states-the-assertions.md) - Assert in a test exactly what its name states, and move every other check into a test with its own name.
- [Trigger every failure case in a test](rules/tests/trigger-every-failure-case.md) - Give every case of a function's error union a test that produces it, in addition to the successful path.
- [Verify which dependency was called, not only that it worked](rules/tests/verify-the-path-not-only-ok.md) - Assert which dependency a workflow called and with which arguments, for example through a recording fake, instead of only checking that the result is `Ok`.

## Library: FsToolkit.ErrorHandling

- [Choose the computation expression by what the function returns](rules/libraries/fstoolkit-errorhandling/choose-the-ce-by-result-type.md) - Write a function that returns `Task<Result<_, _>>` as `taskResult`, a synchronous chain of results as `result`, and a task of your own state union as `task` with `match!`, binding a `Result` with `let!` or `return!` instead of wrapping it.
- [Use the most specific require function](rules/libraries/fstoolkit-errorhandling/most-specific-require.md) - Express a check with the most specific `require` function of FsToolkit, such as `Result.requireEqual` for a comparison or `Result.requireNotEmpty` for a list, instead of `Result.requireTrue` over a hand-written condition.
- [Bind results with a computation expression, not a match staircase](rules/libraries/fstoolkit-errorhandling/result-expressions-over-match-staircases.md) - Write a sequence of steps that return `Result`, `Option`, or `Task<Result>` as `result { }`, `option { }`, or `taskResult { }` with `let!`, not as nested matches that pass every `Error` on by hand.
- [Collect input errors with validation, fail fast in workflows](rules/libraries/fstoolkit-errorhandling/validation-collects-input-errors.md) - Use `validation { }` with `let!` and `and!` where all errors of independent fields should be reported together, typically when building a domain value from user input, and use `result` or `taskResult` with sequential `let!` everywhere else.

## Library: HTMX

- [Encode untrusted text in views](rules/libraries/htmx/encode-untrusted-html.md) - Render user input and other external text with the view engine's encoded text node, such as `str` in Giraffe.ViewEngine, and keep raw HTML helpers such as `rawText` for trusted or sanitized markup.
- [Render a fragment with the function that renders it in the page](rules/libraries/htmx/fragment-from-page-view.md) - Return a fragment only to htmx requests for a part of the page, render it with the same view function the full page uses for that region, and return the full page to every other request.
- [Re-render a form with the submitted values](rules/libraries/htmx/keep-input-on-field-errors.md) - Render a form that failed validation with the submitted editable values, including selections and checkbox state, while clearing secrets and regenerating server-controlled values.
- [Send out-of-band fragments only to targets that exist](rules/libraries/htmx/oob-swaps-need-a-target.md) - Send an out-of-band fragment only when every page that can trigger the request contains its target, and provide an in-band fallback for required feedback when that cannot be guaranteed.
- [Use the htmx helpers of your view library](rules/libraries/htmx/typed-htmx-attributes.md) - Write htmx attributes with the helpers of the installed library, such as `_hxGet` in Giraffe.ViewEngine.Htmx, `.hxGet(...)` in Oxpecker.Htmx, or `Hx.get` in Falco.Htmx, and take URLs and target ids from one definition.
- [Name every header that selects the response in Vary](rules/libraries/htmx/vary-on-hx-request.md) - Append every request header that decides between fragment and full page, such as `HX-Request`, `HX-History-Restore-Request`, `HX-Target`, or `HX-Request-Type`, to the response's `Vary` header.
- [Give view functions parameters that state the intent](rules/libraries/htmx/views-take-intent-parameters.md) - Give a view function parameters that say what the caller wants, such as a small union for how it is updated, instead of lists of raw attributes or nodes that it splices into its markup.
