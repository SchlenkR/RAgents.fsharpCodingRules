# Rule index

Generated by `dotnet fsi scripts/check.fsx` from the rule files. Do not edit by hand.

One line per rule: its core sentence. Agents that write code load this file and open a rule file when
they touch its subject or need its exceptions. Reviewers always get the full rule file.

## Formatting

- [Leave layout to the formatter](rules/formatting/formatter-owns-layout.md) - Write new code in the layout Fantomas produces with the repository's `.editorconfig`, and change the layout only of lines whose content you change.
- [Put multiline brackets on lines of their own](rules/formatting/multiline-brackets-aligned.md) - Write a record, anonymous record, or list either on one line or with the opening bracket on its own line, the content indented one level, and the closing bracket on its own line. (formatter or linter) Pick one: alternative to `multiline-brackets-stroustrup`.
- [Open multiline brackets at the end of the line](rules/formatting/multiline-brackets-stroustrup.md) - Write a record, anonymous record, or list either on one line or with the opening bracket at the end of the binding line, the content indented one level, and the closing bracket on its own line. (formatter or linter) Pick one: alternative to `multiline-brackets-aligned`.
- [Write punctuation you can type](rules/formatting/plain-keyboard-characters.md) - Use plain keyboard punctuation in code, comments, and string literals: `-`, `->`, `...`, and straight quotes instead of typographic dashes, arrows, ellipses, and curly quotes. (formatter or linter)

## Naming and comments

- [Use as for views and to for transformations](rules/naming/as-vs-to-conversions.md) - Name a conversion `asX` only when it changes the view of the same data, such as a cast or a wrapper without copying, and `toX` when it computes new data in another format, unit, or domain.
- [Follow the F# casing conventions](rules/naming/casing-conventions.md) - Use PascalCase for namespaces, modules, types, union cases, and members, and camelCase for let-bound values, functions, and parameters; choose one casing for record fields per code base and keep it. (formatter or linter)
- [Comment only what the code cannot say](rules/naming/comments-say-why.md) - Write a comment only for what names and types cannot express, such as a constraint of an external system or the reason for a surprising decision, in one or two plain lines.
- [Name functions after what they return](rules/naming/name-by-result.md) - Name a function after its result or its effect and a value after its content, so that the call site tells what comes back and from which side.

## Scope and structure

- [Resolve dependency cycles instead of using rec](rules/scope/compile-order-without-rec.md) - Declare types and functions before their users, in file order and within a file, and resolve a dependency cycle by restructuring rather than with `module rec`, `namespace rec`, or `and` between unrelated types.
- [Nest single-use bindings in their consumer](rules/scope/nest-single-use-bindings.md) - Declare a function or value that only one function uses inside that function, directly below its head, and move it to module level when a second consumer appears. Pick one: alternative to `top-level-helpers`.
- [Require qualified access for generic names](rules/scope/require-qualified-access.md) - Mark a union `[<RequireQualifiedAccess>]` when a case name alone does not say which type it belongs to, and a module when its function names are generic, instead of prefixing every name by hand.
- [Shadow successive versions of a value](rules/scope/shadow-successive-versions.md) - Rebind a value under the same name when each step replaces the previous version, instead of numbering the names or reassigning a mutable variable.
- [Keep helper functions flat at module level](rules/scope/top-level-helpers.md) - Declare named helper functions at module level, `private` when they are not part of the module's API, instead of nesting them inside their consumer. Pick one: alternative to `nest-single-use-bindings`.

## Types and domain modeling

- [Make illegal states unrepresentable](rules/types/illegal-states-unrepresentable.md) - Model a value whose fields are valid only in certain combinations as a union with one case per state, each case carrying only the data that exists in that state.
- [Name the cases instead of using bool, Choice, or tuples](rules/types/name-the-cases.md) - Represent a distinction between domain cases as a union with named cases, also for only two cases, instead of a `bool` parameter, `Choice<_, _>`, or a tuple whose parts differ only by position.
- [Use option for missing values, not null](rules/types/option-not-null.md) - Represent a value that may be missing as `option`, or `voption` on hot paths, and convert .NET nulls where they enter, with `Option.ofObj` or `Option.ofNullable`.
- [Attach units of measure to quantities that meet other units](rules/types/units-of-measure.md) - Declare units of measure for numeric quantities when values of different units or scales meet in the same code, such as grams and kilograms or cents and euros.
- [Wrap constrained primitives in single-case unions](rules/types/wrap-constrained-primitives.md) - Give a primitive that carries a domain rule or identifies one kind of entity its own single-case union with a private constructor and a `TryCreate` that returns `Result`.

## Functions and control flow

- [Confine mutation to the block that builds a value](rules/functions/confine-mutation.md) - Use `let mutable` or a mutable collection only inside the block that computes a value, so that only the finished, immutable result leaves it.
- [Curry module functions and tuple members](rules/functions/curry-functions-tuple-members.md) - Give functions in modules curried parameters, ordered from the least to the most varying with the piped data last, and give members of types that .NET code calls tupled parameters.
- [Prefer simple reductions over compound folds](rules/functions/loops-over-compound-folds.md) - Replace a `fold` whose accumulator is a tuple or record, and every `||>` fold, by specific functions such as `sumBy`, `partition`, or `groupBy`, a comprehension, or a `for` loop over a confined `let mutable`.
- [Distinguish domain cases with match](rules/functions/match-domain-cases.md) - Use `match` when code decides between domain cases, also for two cases, instead of `if`/`elif` chains, `.IsCase` properties, or a wildcard over your own union.
- [Name the data instead of composing point-free](rules/functions/name-the-data.md) - Define module-level functions with named, annotated parameters and a pipeline, not as point-free compositions with `>>` or partial applications.
- [Define operators only as aliases of named functions](rules/functions/operators-as-named-aliases.md) - Define a custom operator only in a module that is opened on purpose, such as a DSL or combinator module, and only as a one-line alias of a named function that callers can use instead.

## Errors

- [Avoid functions that throw on missing data](rules/errors/avoid-partial-functions.md) - Use `tryHead`, `tryFind`, `tryItem`, `Map.tryFind`, or a match instead of `List.head`, `List.find`, `Seq.exactlyOne`, `Map.find`, `Option.get`, or `.Value` on an option when the data may be missing.
- [Catch exceptions only at boundaries](rules/errors/catch-at-boundaries.md) - Write `try`/`with` only directly around a call that throws for an expected reason, such as parsing, a file, an SDK, or legacy code, and classify the exception right there; never wrap your own core logic or swallow exceptions.
- [Return expected failures as values, not exceptions](rules/errors/expected-failures-are-values.md) - Return a business failure that callers handle, such as invalid input, an unknown key, or a violated rule, as `Result` or `Option` instead of `failwith`, `raise`, or `invalidOp`.
- [Rethrow with reraise](rules/errors/reraise-keeps-stack.md) - Rethrow the exception being handled with `reraise ()`, not with `raise ex`, and wrap it in a new exception only to add context, passing the original as the inner exception. (formatter or linter)
- [Return Result only for failures a caller acts on](rules/errors/result-for-decisions.md) - Use a `Result` error case only when some caller matches on it and does something different, and let failures nobody can handle, such as an unavailable database, raise exceptions caught once at the top.

## Design

- [Abstract only for a second real use](rules/design/abstract-on-second-use.md) - Introduce a generic type parameter, an interface, a configuration switch, or a shared helper only when a second real use exists, not in anticipation, and let small blocks repeat until then.
- [Keep F# APIs idiomatic and add a facade for C#](rules/design/csharp-facade.md) - Write APIs that F# code calls with F# types, such as lists, options, function types, and unions, and when C# code consumes the library, add a separate facade that converts to .NET types.
- [Keep types as data and functions in a companion module](rules/design/functions-in-companion-module.md) - Define records and unions as plain data and put their functions, including construction and projections, in a module of the same name directly after the type, such as `Invoice.total`. Pick one: alternative to `members-for-own-data`.
- [Pass a function or a value instead of a single-use interface](rules/design/functions-over-single-use-interfaces.md) - Take a dependency as a function parameter, or better as the value it would produce, instead of defining an interface, unless several operations belong together or two real implementations exist.
- [Keep I/O at the edges of a workflow](rules/design/io-at-the-edges.md) - Structure a workflow as read, decide, write: load the data, compute the decision in a pure function that receives values, then perform the effects the decision describes.
- [Put on a type what needs only its own data](rules/design/members-for-own-data.md) - Define construction (`TryCreate`), projections (`Value`, `Total`), and state transitions that use only the type's own data as members of the type, and put functions that need I/O, combine several types, or work on collections into a module. Pick one: alternative to `functions-in-companion-module`.
- [Use modules for logic and classes only for state with a lifetime](rules/design/modules-for-logic.md) - Write logic as functions in modules over records and unions, and define a class only when something owns mutable state, a resource, or a lifetime, or when a framework requires one.
- [Use task for I/O in .NET applications](rules/design/task-for-dotnet-io.md) - Write asynchronous application code that calls .NET APIs as `task { }`, pass a `CancellationToken` explicitly where work must be cancellable, and use `async { }` only where its cold start or implicit cancellation is needed.

## Library: FsToolkit.ErrorHandling

- [Bind results with a computation expression, not a match staircase](rules/libraries/fstoolkit-errorhandling/result-expressions-over-match-staircases.md) - Write a sequence of steps that return `Result`, `Option`, or `Task<Result>` as `result { }`, `option { }`, or `taskResult { }` with `let!`, not as nested matches that pass every `Error` on by hand.
- [Collect input errors with validation, fail fast in workflows](rules/libraries/fstoolkit-errorhandling/validation-collects-input-errors.md) - Use `validation { }` with `let!` and `and!` where all errors of independent fields should be reported together, typically when building a domain value from user input, and use `result` or `taskResult` with sequential `let!` everywhere else.

## Library: HTMX

- [Render a fragment with the function that renders it in the page](rules/libraries/htmx/fragment-from-page-view.md) - Return a fragment only to htmx requests that are not history restores, render it with the same view function the full page uses for that region, and return the full page to every other request.
- [Use the htmx helpers of your view library](rules/libraries/htmx/typed-htmx-attributes.md) - Write htmx attributes with the helpers of the installed library, such as `_hxGet` in Giraffe.ViewEngine.Htmx, `.hxGet(...)` in Oxpecker.Htmx, or `Hx.get` in Falco.Htmx, and take URLs and target ids from one definition.
- [Send Vary: HX-Request when a URL serves fragments and pages](rules/libraries/htmx/vary-on-hx-request.md) - Add `Vary: HX-Request` to every response of a URL that returns a fragment or a full page depending on the htmx request headers.
